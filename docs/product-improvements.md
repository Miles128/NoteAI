# 产品改进选型清单

> 来源：2026-08 全项目产品分析。
>
> **核心判断：编译侧已是同类最深实现，短板在消费侧——AI 产出如何被日常使用、验证、回流。**
>
> 本文档为选型清单：每项含复选框、优先级与工作量预估（S ≈ 1 天内 / M ≈ 2-4 天 / L ≈ 1 周以上），请逐条勾选是否实施。

---

## 高优先级（直接影响留存与核心价值感知）

### P1. 首页知识动态卡片 + 一键周报（暂缓）

- [ ] 实施本项

- **优先级**：P1（高）
- **工作量**：M
- **现状与问题**：语义编译产出（命题/实体/知识变化摘要）只能在语义工作台概览看到；普通用户不主动打开工作台，就感知不到知识库在"生长"。
- **依据**：PRD §2 核心循环"回顾与输出"支柱、§11.3（每日/每周回顾 P1 未落地）；`get_semantic_changes` RPC 已具备数据基础。
- **改进建议**：首页 dashboard 增加"知识动态"卡片（本周新增命题 Top N、失效/更新结论、待审阅冲突、新增实体），并提供一键生成本周简报、保存为笔记；数据复用现有只读 RPC，仅简报生成调 LLM。
- **预期用户价值**：把"知识在增值"变成每天可见的事实，是相对 NotebookLM 静态 notebook 最独特的叙事。

### P2. 首启引导 wizard ✅ 已选 · 待实施

- [x] 实施本项

- **优先级**：P2（高）
- **工作量**：L
- **现状与问题**：上手靠 README 手工四步，三重门槛叠加——自备 LLM API Key、embedding/reranker 模型首次联网下载（FlagReranker 体积大、耗时不可预期）、示例库创建与提问体验不串联；`webui/js` 无任何 onboarding 实现。
- **依据**：PRD §2 首次体验、README 上手流程；`download_callback` 已存在但缺 UI 承接。
- **改进建议**：线性 wizard——选工作区 →「先用示例库体验」→ API Key 页提供服务商预设模板（DeepSeek/OpenAI/Ollama）+ 连通性测试 → 静默建索引并显示模型下载进度条 → 自动在示例库发起示范提问（预置问题让用户第一次就看到带引用的回答与命题溯源）。
- **预期用户价值**：把配置门槛转化为进度可见的初始化体验，首次会话即展示引用溯源核心卖点。

### P3. RAG 引用溯源到段落/标题级 + 无证据显式声明（暂缓）

- [ ] 实施本项

- **优先级**：P3（高）
- **工作量**：M
- **现状与问题**：引用只能定位到文件（docs/rag-intent-router-analysis.md §8.3 长期项未完成）；PRD §8 要求事实紧随有效引用编号，但点开引用无法跳到证据段落，验证成本高。语义工作台侧 Evidence 已能定位标题路径，说明 chunk 已存 section 信息，RAG 引用侧只是没透出。
- **依据**：docs/rag-intent-router-analysis.md §8.3；PRD §8 引用规则；chunk 中的 section 字段。
- **改进建议**：引用对象增加 section_title/块摘要字段，点击后打开文件并滚动定位对应标题；无证据支撑时显式输出"知识库暂无直接证据"提示块。
- **预期用户价值**：把"可追溯"从口号变成 2 秒内可完成的验证动作。

### P4. 多轮对话增强 ✅ 已选 · 待实施

- [x] 实施本项

- **优先级**：P4（高）
- **工作量**：M
- **现状与问题**：L2 只携带最近 6 条消息（`rag_handler._limited_history`），更早历史仅取前 800 字符抽取式压缩；意图分类时 history 未参与（划词路由传空 history），"它呢？"类指代问题易误路由。
- **依据**：`python/sidecar/handlers/rag_handler.py`；docs/rag-intent-router-analysis.md；PRD §3/§12.6 边界约束。
- **改进建议**：① 意图分类注入最近 2 轮历史；② 会话内轻量主题锚定（当前讨论主题/实体注入检索过滤，不持久化）；③ 回答下方提供 2-3 个基于引用来源的追问建议。约束：必须保持在 PRD §3/§12.6"不持久化、不自动提炼"边界内。
- **预期用户价值**：问答从一次性检索升级为研究式对话。

## 中优先级

### P5. AI 产出可信度可见化 ✅ 已选 · 待实施

- [x] 实施本项

- **优先级**：P5（中）
- **工作量**：S
- **现状与问题**：语义页/综述带生成时间与输入摘要（PRD §10.2），但读者看不到"基于哪几篇笔记、是否过期、证据覆盖如何"；PRD §10.6/§12 的信任规则未转化为读者可见 UI。
- **依据**：PRD §10.2、§10.6、§12；主题树"可更新"蓝色徽标机制。
- **改进建议**：综述/语义页头部轻量元信息条——基于 N 篇笔记、最后编译时间、可更新状态（主题树已有蓝色徽标可同步正文页）、未裁决冲突显式标注。
- **预期用户价值**：竞品均无此能力，是差异化展示点。

### P6. 输出形态多元化（编译产物）（暂缓）

- [ ] 实施本项

- **优先级**：P6（中）
- **工作量**：L
- **现状与问题**：AI 输出只有 Markdown 综述与保存的问答笔记；NotebookLM Studio 已提供简报、FAQ、学习指南、闪卡等一键产物且随笔记更新同步。NoteAI 拥有更好的底层（命题+证据）但输出形态单一。
- **依据**：竞品 NotebookLM Studio；`prompts/yaml/` 模板机制；TopicState/活跃命题数据。
- **改进建议**：主题综述页增加"生成"菜单——研究简报（跨主题）、FAQ、周报草稿，基于 TopicState/活跃命题生成并保留引用，模板复用现有 prompt yaml 机制；音频类后置。
- **预期用户价值**：把"编译"价值从整理扩展到输出，覆盖核心循环最后一环。

### P7. 语义工作台认知门槛降低 ✅ 已选 · 待实施

- [x] 实施本项

- **优先级**：P7（中）
- **工作量**：S
- **现状与问题**：工作台功能完整但对象语言（Claim/Evidence/inactive）面向治理者而非普通读者，概览只有数字，新用户不知道"对我有什么用"。
- **依据**：PRD §10.10 验收约束；语义工作台概览页现状。
- **改进建议**：概览页增加"你的知识库"叙事卡片（已沉淀 X 条结论、覆盖 Y 个主题、本周新增 Z 条）；对象列表用语本地化为"结论/证据/疑问"；镜像知识动态。不改动底层数据与 PRD §10.10 验收约束。
- **预期用户价值**：语义层从黑盒数据库变成产品第二主界面。

### P8. 知识图谱主题层探索视图（暂缓）

- [ ] 实施本项

- **优先级**：P8（中）
- **工作量**：M
- **现状与问题**：图谱是笔记/主题/标签的力导向展示，全库 Chunk 相似度地图为 Pending（PRD §9.5 明确不进当前版本），无聚类/孤岛分析视角。
- **依据**：PRD §9.5；现有图谱实现与主题综述/embedding 数据。
- **改进建议**：不直接做 Chunk 级大图，先上主题层轻量视图——主题簇 + 孤岛主题高亮 + 主题间距离（数据可用现有主题综述/embedding 聚合）；待确认双向链接虚线呈现并支持就地确认。
- **预期用户价值**：图谱从装饰变为整理巡检的可视化入口。

### P9. RAG 检索透明化（调试面板） ✅ 已选 · 待实施

- [x] 实施本项

- **优先级**：P9（中）
- **工作量**：S
- **现状与问题**：用户看不到实际检索到哪些片段，只能看最终引用，召回不佳时只能归咎产品（分析文档 §7.3）。
- **依据**：docs/rag-intent-router-analysis.md §7.3；现有检索中间结果。
- **改进建议**：AI 面板增加"展开检索过程"折叠区（默认折叠）：意图分类结果、检索片段及得分、是否触发 HyDE；成本只是透出已有中间结果。
- **预期用户价值**：提升高级用户信任与反馈质量，便于内部调优。

### P10. 本地数据安全入口显性化（暂缓）

- [ ] 实施本项

- **优先级**：P10（中）
- **工作量**：M
- **现状与问题**：备份/恢复、索引健康检查能力存在但入口分散；PRD §11.5 可移植导出/工作区迁移仍是路线项。对把全部知识托付给本应用的本地优先产品，数据安全感可见入口不足。
- **依据**：PRD §11.5；现有备份/恢复与索引健康检查能力。
- **改进建议**：设置页增加"数据安全"分区——一键备份（显示上次备份时间）、导出为纯 Markdown+语义库 zip、索引健康自检与重建按钮。
- **预期用户价值**：本地优先定位的信任闭环，Obsidian 用户转化的关键因素。

## 差异化定位小结

- **相对 NotebookLM**：应加倍投入本地数据主权、增量编译、命题级溯源；先追"5 分钟可体验"（P2）与"变化可见"（P1）。
- **相对 Obsidian + AI 插件**：把"引用可点开定位、结论可追溯失效"（P3、P5）做成插件组合无法复制的体验。
