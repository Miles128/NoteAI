# NoteAI PRD — AI 原生个人知识库

**版本**：v3.0  
**日期**：2026-06-30  
**状态**：产品方向重构

---

## 1. 产品定位

**一句话**：AI 帮你整理、编译、管理知识库，你只管丢资料进去。

**目标用户**：不想费劲整理、也不想从零开始的知识工作者。

**灵感**：Karpathy LLM Wiki — Stop re-deriving, start compiling.

**与竞品的区别**：
- Obsidian + ChatGPT = 两套系统，每次提问从零开始
- NoteAI = 采集 → 整理 → 编译 → 操作，一站式闭环

---

## 2. 核心循环

```
丢资料 → AI 整理(分类/标签/链接) → AI 编译(综述/WIKI) → CLI agent 操作
```

三大支柱：

| 支柱 | 职责 |
|---|---|
| **整理** | 自动分类、标签提取、双向链接发现 |
| **编译** | 综述生成/级联更新（阅读层 + RAG 索引层双重用途） |
| **CLI Agent** | 执行文件操作（移动、创建主题、归档） |

RAG 定位为辅助检索，不是核心支柱。

---

## 3. 关键架构决策

| 项 | 决策 |
|---|---|
| 三层架构 | 保留 Notes / wiki / Raw |
| Ingest pipeline | 默认**关**（惰性），设置可切换为主动触发 |
| 综述生成 | 批量入库结束后**后台异步**生成，UI 提示「正在生成」 |
| RAG vs CLI | 分离，不合并意图路由 |
| 对话记忆 | 不做 L1/L2 记忆体系 |

## 6. 后续开发：划词检索 / 联网搜索

**目标**：用户在笔记内部选中某个词、短句或段落后，可以直接触发知识库检索或联网搜索，快速理解上下文，而不打断当前阅读 / 写作流。

### 6.1 用户体验

选中文本后，在选区附近显示极简浮动工具条：

| 动作 | 行为 |
|---|---|
| 问知识库 | 使用选中文本 + 当前段落上下文触发 RAG，回答必须带引用 |
| 联网搜索 | 使用选中文本触发联网搜索，回答必须带网页来源 |

第一版只做「问知识库」和「联网搜索」。不自动修改笔记。

### 6.2 产品边界

- 划词功能只负责查找、解释、补充背景。
- 不自动写回当前笔记。
- 若要插入结果，必须显式点击「插入当前位置」或「追加为补充说明」。
- 文件移动、创建、归档等操作继续交给 CLI Agent。
- RAG 仍然只做「问知识库并给引用」，不做文件操作。

### 6.3 查询构造

选中文本较短时，必须带当前段落上下文，避免短词误检索。

```
选中文本：{selection}
所在笔记：{current_file}
上下文：{paragraph_context}

请基于知识库解释选中文本，与当前笔记上下文相关即可。必须引用来源。
```

联网搜索模式：

```
请联网搜索并解释以下选中文本，优先给出权威来源：
{selection}

如果这是术语，请解释定义、背景、与当前上下文的关系。
```

### 6.4 技术方案

- 前端新增 `selection-lookup.js`，监听 Tiptap 编辑器 selection update。
- 浮动工具条只在编辑器激活且选区文本长度为 2-500 字时出现。
- 「问知识库」复用 RAG Assistant 面板，调用 `rag_chat` 或后续扩展 `rag_chat` 的 `mode=rag`。
- 「联网搜索」扩展 `rag_chat` 参数 `force_intent=web`，避免短词被 intent router 误判。
- 结果默认进入右侧 RAG Assistant，复用现有 streaming、引用渲染和动态 top-K。

### 6.5 P0 切片

1. 选区浮动工具条。
2. 问知识库：复用 RAG 对话与引用。
3. 联网搜索：强制 web intent。
4. Assistant 消息标记「来自划词：xxx」。
5. JS smoke + 后端 intent 参数测试。
