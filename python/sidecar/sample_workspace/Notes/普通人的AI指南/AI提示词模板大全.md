# AI提示词模板大全

## 使用说明

每个模板中的 `[占位符]` 替换为你的实际内容。模板按场景分类，可直接复制使用，也可根据需要调整。

---

## 1. 角色扮演类

### 1.1 领域专家

```
你是一位拥有20年经验的[领域]专家。请基于你的专业知识，[具体任务]。

要求：
- 使用专业但易懂的语言
- 给出具体可操作的建议
- 如有行业最佳实践，请一并说明
- 标注建议的置信度（高/中/低）
```

### 1.2 面试官

```
你是一位资深[岗位]面试官，来自[公司类型]企业。请对我进行模拟面试。

规则：
- 每次只问一个问题
- 等我回答后，给出评价和追问
- 难度逐步递增
- 覆盖[技术/行为/系统设计]类问题
- 最后给出综合评分和改进建议
```

### 1.3 代码审查员

```
你是一位严格的代码审查员，请审查以下代码：

[粘贴代码]

审查维度：
1. 正确性：逻辑是否有 bug
2. 安全性：是否有安全漏洞
3. 性能：是否有性能瓶颈
4. 可读性：命名、结构、注释
5. 可维护性：是否易于修改和扩展

对每个问题标注严重程度（🔴 严重 / 🟡 建议 / 🟢 可选），并给出修改建议。
```

### 1.4 辩论对手

```
请你扮演我观点的反方，与我进行辩论。

我的观点：[你的观点]

规则：
- 每轮提出一个反驳论点
- 引用事实和逻辑，不使用情绪化语言
- 如果我的论点有道理，请承认
- 如果发现我的论点有漏洞，明确指出
- 每轮发言控制在200字以内
```

## 2. 写作创作类

### 2.1 文章撰写

```
请写一篇关于[主题]的文章。

目标读者：[读者画像]
文章风格：[学术/通俗/专业/轻松]
字数要求：[字数]字左右
核心观点：[你想表达的核心观点]

结构要求：
- 开头：用[数据/故事/问题]引入
- 正文：分[3-5]个论点展开，每个论点配[案例/数据]
- 结尾：总结并给出[行动建议/展望]
```

### 2.2 公众号文章

```
请写一篇微信公众号文章。

主题：[主题]
目标：[涨粉/品牌/转化/教育]
调性：[专业/轻松/情感/干货]

要求：
- 标题：给出3个备选，使用[数字/疑问/对比]式
- 开头：3秒内抓住注意力
- 正文：短段落，每段不超过3行
- 配图建议：标注每段适合配什么图
- 结尾：引导[关注/点赞/转发/评论]
```

### 2.3 邮件撰写

```
请帮我写一封[类型]邮件。

收件人：[关系/职位]
目的：[请求/通知/道歉/感谢/跟进]
关键信息：[需要传达的核心内容]
语气：[正式/友好/紧急/委婉]
长度：[简短/适中/详细]

要求：
- 主题行：简洁明确
- 开头：直接说明目的
- 正文：要点清晰
- 结尾：明确的下一步行动
```

### 2.4 周报/汇报

```
请帮我写一份[周报/月报/季度汇报]。

时间范围：[日期]
我的角色：[职位]

本周完成：
- [事项1]
- [事项2]
- [事项3]

进行中：
- [事项1]：进度[X%]，卡点[...]
- [事项2]：进度[X%]

下周计划：
- [事项1]
- [事项2]

要求：
- 用数据说话，量化成果
- 问题附带解决方案
- 控制在[字数]字以内
```

## 3. 编程开发类

```

约束：
- 不改变外部行为（功能等价）
- [其他约束]

请：
1. 说明当前代码的问题
2. 给出重构后的代码

### 3.5 单元测试

```

[粘贴代码]

要求：
- 覆盖正常路径和异常路径
- 包含边界条件测试
- 使用有意义的测试命名
- Mock 外部依赖
- 每个测试只验证一个行为
```

## 4. 数据分析类

### 4.1 数据解读

```
请分析以下数据并给出洞察：

数据：
[粘贴数据或描述数据来源]

分析维度：
- 趋势：整体走向如何？
- 异常：有没有异常值？可能原因？
- 相关性：变量之间是否有关联？
- 行动建议：基于数据应该做什么？

输出格式：
- 用通俗语言解释，避免纯统计术语
- 每个洞察配数据支撑
- 给出置信度评估
```

### 4.2 SQL 查询

```
请帮我写一个 SQL 查询。

数据库：[MySQL/PostgreSQL/其他]
表结构：
[描述表结构或粘贴 DDL]

需求：[用自然语言描述查询需求]

要求：
- 考虑查询性能（适当使用索引提示）
- 处理 NULL 值
- 添加注释说明复杂逻辑
- 提供替代方案（如有更优写法）
```

### 4.3 竞品分析

```
请对以下产品进行竞品分析。

我的产品：[产品名称和简介]
竞品列表：[竞品1]、[竞品2]、[竞品3]

分析维度：
1. 定位对比：目标用户、核心价值
2. 功能对比：核心功能差异
3. 定价对比：商业模式和价格
4. 优势劣势：各自的长短板
5. 市场策略：获客方式和增长路径
6. 对我的启示：可借鉴和需规避的

输出格式：对比表格 + 分析总结
```

## 6. 商业职场类

### 6.1 产品需求文档

```
请帮我撰写一份产品需求文档（PRD）。

产品/功能：[名称]
目标用户：[用户画像]
核心痛点：[解决什么问题]

请包含：
1. 背景与目标
2. 用户故事（As a... I want... So that...）
3. 功能需求（P0/P1/P2 优先级）
4. 非功能需求（性能/安全/兼容性）
5. 交互流程（核心路径）
6. 数据指标（衡量成功的指标）
7. 风险与依赖
```

### 6.2 商业计划

```

[粘贴笔记/录音转写]

1. 会议摘要（3句话以内）
2. 关键决策（列出所有决定）
3. 行动项（负责人 + 截止日期 + 交付物）

## 8. 高级技巧类

### 8.1 思维链（Chain of Thought）

```
请一步步思考以下问题，展示你的推理过程。

问题：[问题]

要求：
- 写出每一步的思考过程
- 如果某步不确定，标注出来
- 如果发现推理有误，回溯修正
- 最后给出结论及置信度
```

### 8.2 少样本学习（Few-shot）

```
请按照以下示例的格式和风格完成任务。

示例1：
输入：[示例输入1]
输出：[示例输出1]

示例2：
输入：[示例输入2]
输出：[示例输出2]

示例3：
输入：[示例输入3]
输出：[示例输出3]

现在请处理：
输入：[你的实际输入]
输出：
```

### 8.3 自我批评（Self-Critique）

```
请完成以下任务，然后对自己的输出进行批评和改进。

任务：[任务描述]

流程：
1. 给出初始回答
2. 审视初始回答的不足：
   - 是否有逻辑漏洞？
   - 是否遗漏了重要方面？
   - 是否有不准确的地方？
3. 给出改进版本
```

### 8.4 角色切换（Perspective Taking）

```
请从以下三个不同视角分析[问题/决策]：

视角1 - 乐观派：这个方案最大的机会是什么？
视角2 - 悲观派：最可能出什么问题？
视角3 - 务实派：落地执行的关键卡点在哪？

每个视角给出3个核心论点，最后给出综合建议。
```

### 8.5 迭代优化（Iterative Refinement）

```
我将给你一个初始版本，请你进行多轮优化。

初始版本：
[内容]

优化方向：
- 第1轮：提升准确性（检查事实和逻辑）
- 第2轮：提升清晰度（简化表达，去除冗余）
- 第3轮：提升影响力（增强说服力和感染力）

每轮输出优化后的版本，并说明改动了什么、为什么。
```

## 9. Agent/System Prompt 类

### 9.1 通用 Agent 系统提示

```
你是一个专业的 AI 助手，名叫[名称]。

## 核心原则
- 先理解，再回答。不确定时主动询问
- 给出具体可操作的建议，而非泛泛而谈
- 承认不知道，不编造信息
- 用数据和逻辑支撑观点

## 行为规范
- 当用户请求不明确时，提出澄清问题
- 当任务复杂时，先列出计划再执行
- 当可能出错时，提醒风险并给出替代方案
- 始终使用[语言]回答

## 禁止事项
- 不要编造数据或引用
- 不要给出可能造成损害的建议
- 不要跳过推理直接给结论
```

### 9.2 编程 Agent 系统提示

```
你是一位资深全栈工程师，负责[项目类型]项目的开发。

## 技术栈
- 前端：[框架]
- 后端：[框架]
- 数据库：[类型]
- 部署：[平台]

## 编码规范
- 遵循项目现有代码风格
- 每次修改前先理解上下文
- 修改代码后必须验证（运行测试/lint）
- 不确定时使用 Plan Mode，先分析再动手

## 工作流程
1. 理解需求 → 2. 制定方案 → 3. 实现 → 4. 测试 → 5. 提交

## IMPORTANT
- 不要删除现有代码除非明确要求
- 不要引入项目未使用的依赖
- 每次只做一件事，做完验证再做下一件
```

### 9.3 客服 Agent 系统提示

```
你是[公司名]的客服代表。

## 服务准则
- 始终保持友好和耐心
- 先共情，再解决问题
- 给出明确的时间线和下一步

## 知识边界
- 产品信息：[知识库范围]
- 可处理问题：[退款/查询/投诉/...]
- 需升级处理：[超出权限的问题类型]

## 回复模板
- 投诉：道歉 → 共情 → 方案 → 跟进
- 查询：确认 → 查找 → 回复 → 确认满意
- 退款：确认资格 → 说明流程 → 预计时间

## 禁止
- 不要承诺无法保证的事项
- 不要透露内部流程细节
- 不要与客户争论
```

## 11. 提示词优化模板

### 11.1 提示词自检清单

写完提示词后，逐项检查：

| 检查项 | 是否满足 |
|--------|---------|
| 角色是否明确？ | ☐ |
| 任务是否具体？ | ☐ |
| 输出格式是否指定？ | ☐ |
| 约束条件是否列出？ | ☐ |
| 示例是否提供？ | ☐ |
| 质量标准是否定义？ | ☐ |
| 边界情况是否考虑？ | ☐ |

### 11.2 提示词优化公式

```
好的提示词 = 角色 + 任务 + 上下文 + 格式 + 约束 + 示例

角色：你是谁
任务：做什么
上下文：为什么做、背景是什么
格式：输出什么样
约束：不能做什么、边界在哪
示例：好的输出长什么样
```

### 11.3 常见反模式与修正

| 反模式 | 问题 | 修正 |
|--------|------|------|
| "帮我写篇文章" | 太模糊 | 指定主题、读者、风格、字数 |
| "写得好一点" | 标准不明 | 定义"好"的标准（清晰/专业/有数据） |
| "尽可能详细" | 无边界 | 指定字数/要点数/深度 |
| 一次问多个问题 | 模型可能遗漏 | 分步提问或编号列出 |
| 不给示例 | 输出格式不可控 | 提供1-3个示例 |
| 只说不要什么 | 缺少正向引导 | 同时说"要什么"和"不要什么" |
